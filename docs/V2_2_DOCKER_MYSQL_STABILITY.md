# SASS HRM Enterprise — MySQL/Docker Stability Release (v2.2)

## Intended deployment

**For local/private development only.** The stack is bound to `127.0.0.1`. It is not a public internet deployment and is not approved for real sensitive employee data until security reviews, backup restoration, compliance checks and access controls have been validated independently.

The latest frontend, backend and MySQL services share one Docker Compose network:

```
Browser :5173 -> nginx (built React) -> /api/* -> FastAPI :8000 -> MySQL :3306
                                                              |
                                                            volume
```

Local MySQL Workbench access remains `127.0.0.1:3307`, using credentials generated by `SETUP_SASS_HRM.bat`. Backend container traffic uses internal host `mysql:3306`; it does not depend on the Windows IP address. The same `sass_hrm_real` Compose project and `sass_hrm_mysql_data` named volume are shared by the original MySQL-only launcher and the new full stack. **Never use `docker compose down --volumes` or `docker volume rm` with real HR records.**

## First-time local installation

1. Install and start Docker Desktop (Linux containers). Stop any old SASS HRM Vite or Python processes occupying ports `5173`, `8000`, or MySQL port `3307`.
2. Run `SETUP_SASS_HRM.bat` **only when setting up a new database**. It generates matching configuration and random secrets in `.env` and `server/.env`; these are excluded from the ZIP.
3. Run `START_DOCKER_FULL.bat`. It verifies configuration, builds both images, starts services, and checks the API and reverse proxy. The first build requires access to npm and PyPI.
4. On a new and completely empty database only, run `CREATE_ADMIN.bat` (requires local Python and access to port 3307). The administrator enters their own password through a local hidden prompt. Do not rerun on an existing organization database.
5. Open `http://localhost:5173`. Run `VERIFY_DOCKER_FULL.bat` and `VERIFY_EVERYTHING.bat` for infrastructure/API and isolated backend/frontend tests respectively.

**Existing installation:** Back up first (`BACKUP_MYSQL.bat`). Keep the original matching `.env`, `server/.env`, and MySQL Docker volume. Never run the first-time setup or reset generated database secrets against a populated volume. Restore backups only into a separate test database after review.

## Check services manually

```powershell
# Run from the SASS_HRM_Enterprise folder.
docker compose -f docker-compose.full.yml ps
docker compose -f docker-compose.full.yml logs --tail 80 api
docker compose -f docker-compose.full.yml logs --tail 80 mysql
docker compose -f docker-compose.full.yml logs --tail 80 web
```

Service health endpoints:
- `http://localhost:8000/api/health` — confirms FastAPI can make a database query, with `database: mysql`.
- `http://localhost:5173/api/health` — confirms the nginx reverse proxy reaches FastAPI and MySQL.
- `http://localhost:5173` — static React application.

A healthy MySQL connection alone **does not** verify payroll rules, every authorized CRUD mutation, browser usability, backup restoration, or cybersecurity compliance. The test scripts under `server/` still use **isolated SQLite synthetic test databases**, to avoid modifying real employees.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| MySQL container unhealthy | Check Docker Desktop, port 3307 conflicts, `docker compose -f docker-compose.full.yml logs mysql`. Old volumes can contain credentials from an earlier setup; do not reset the volume. |
| API unhealthy | Check `server/.env`, JWT key, MySQL credential match, and `logs api`. The API will refuse SQLite except in the isolated test mode. |
| Frontend build fails | Docker builder must reach npm registry; look in the `web` build logs. A browser white screen requires Console inspection. |
| HTTP 502 from nginx | Backend was not ready or the API container is unhealthy. Check `http://localhost:8000/api/health` and the API logs. |
| Setup complains about existing env | You are upgrading an existing installation; do not regenerate secrets. Use matching original configuration. |
| Sign-in fails | Verify administrator was created on the **current** MySQL volume and the old Python/Vite servers are stopped. |

## Limitations and next production tasks

- Docker isn't available in the build workspace, so MySQL container startup and live InnoDB CRUD cannot be independently verified here. Docker Compose was statically validated.
- Node registry access was unavailable; the real React production build remains to be executed in Docker or on Windows with dependencies installed.
- No automated live restore test, penetration test, MFA/SSO integration, statutory payroll compliance approval, public TLS gateway, centralized encrypted key management or multi-organization isolation is included.
- MySQL schema is created by idempotent DDL plus migration markers. Review and adopt a proper migration framework for production upgrades. Do not run a test migration against real employee records without a backup and rehearsal.
- The vault still requires both encryption and a running ClamAV scanner; the Compose stack does not turn these on automatically.
- A full authenticated browser click-through requires user-authorized credentials in the local browser audit script. No credentials are bundled.
